## SCOPE

### P03.1 — First-party secure session and environment boundary

- Laravel Sanctum protects customer API state.
- Customer sessions are first-party cookie sessions rather than client-owned identity tokens.
- Production session/cookie configuration fails closed when secure HTTPS requirements are not met.
- The frontend exposes a narrow same-origin TanStack BFF instead of a generic backend proxy.
- BFF routes are allow-listed and do not concatenate arbitrary splat paths into backend URLs.
- XSRF cookies/tokens and customer cookies are forwarded only through the controlled auth boundary.

### P03.2 — Google OAuth customer identity

- Google is the active P03 customer sign-in path.
- OAuth state and return target are validated.
- Customer sessions rotate on successful authentication.
- Google identity linking is backend-owned.
- Privileged admin identity remains separated from customer authentication.
- Production frontend exposes the real Google login route instead of password/demo registration authority.

### P03.3 — Retained OTP security domain

- OTP infrastructure remains available but is disabled by default in production.
- Real Kavenegar verify/lookup delivery is behind explicit feature/provider configuration.
- OTP codes have TTL, attempt limits, replay protection, resend controls and rate limits.
- Provider secrets remain backend-only and are absent from frontend source.
- P03 does not enable an OTP production UI while the feature flag is OFF.

### P03.4 — Customer profile, mobile, addresses and consent truth

- A normalized Iranian mobile number is mandatory before the account is considered complete.
- Customer profile updates are backend-authoritative.
- Customer addresses enforce ownership.
- Consent changes are recorded as append-only history rather than mutable cosmetic toggles.
- Frontend production account/auth pages consume the authenticated backend session.

### P03.5 — Privacy, export and deletion lifecycle

- Customer data export is backend-owned.
- Account deletion request/cancel workflows are explicit and controlled.
- Final deletion uses controlled pseudonymization rather than unsafe cascades or unaudited raw deletion.
- New User audit records intentionally exclude customer name/email/password PII and retain only security/status evidence.
- A regression test proves customer identity PII is absent from new append-only User audit payloads.
- The customer/session/OTP/account API is registered in backend `docs/openapi/sole-customer-v1.yaml`.

### P03.6 — Frontend integration, performance recovery, QA and closure

- Production `/auth` is isolated from the development demo route and uses the real Google/session boundary.
- Production `/account` is isolated from development local/demo account authority.
- Production account supports profile, addresses, consent history, export, deletion request/cancel and logout.
- Real orders are intentionally not invented; account UI states that production orders are not connected until P06.
- Same-origin TanStack route `/api/auth/$` is generated by the pinned route generator and registered in exact F2/F7 route gates.
- P03 security audit is permanently chained into `audit:production-program`.
- Temporary route/audit synchronization workflows removed themselves before acceptance.
- The expanded Vite production truth guard preserves P01/P02 catalog truth isolation while replacing development auth/account routes in production.
- Production auth/account use dedicated lightweight `ProductionNavbar`, `ProductionFooter` and `ProductionMobileBottomNav` modules. They do not import store state, SearchDialog, NotificationCenter or Framer Motion.
- Vite 8 production builds use Rolldown `output.codeSplitting` with an `entriesAware` shared group so route-specific customer dependencies do not collapse into the homepage entry.
- The accepted F12 performance budget was restored without changing any budget limit.

## EXCLUSIONS

- OTP production UI remains disabled while the backend feature flag is OFF.
- Server-authoritative cart/orders belong to P06.
- Payments, shipping and returns belong to P07.

- P03 does not weaken P02 catalog/media truth or introduce production demo fallback.

- Customer addresses and privacy actions enforce authenticated ownership.
- User audit excludes customer identity PII from new append-only records.

- Production auth/account shell intentionally excludes store/search/notification demo authority and fails closed toward backend-owned account truth.
